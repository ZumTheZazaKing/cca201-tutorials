Two programs print at the same time

A printer can serve only one job at a time. But you never wait in front of it: your computer writes the job into a print queue on disk (the spooler) and gives you control back. That is spooling.

Q1a · mutual exclusion

Do it on your computer

  1. Settings → Bluetooth & devices → Printers & scanners → Microsoft Print to PDF → Open print queue.
  2. In the queue window: Printer → Pause printing.
  3. Print one page from Notepad and one from your browser. Both jobs appear in the queue at once, and both programs are free again.
  4. Optional: press Win+R, services.msc, find Print Spooler: the OS service that owns the real printer.
  5. Resume printing, or cancel the jobs.
  1. System Settings → Printers & Scanners → choose a printer → Printer Queue… → Pause.
  2. Print from two apps: both jobs wait in the queue, both apps are free.
  3. Resume or delete the jobs.

Think: the printer is still used by one job at a time. So what exactly became shared? And what happens if the queue's disk space is full?

Spool space

Each job writes its pages into the spool while it is being created. The printer starts a job only when the job is completely written.

Your browser has a lock manager

Web pages can ask the browser for named locks (navigator.locks). Like an OS, it gives a lock to one task at a time. The tool on the right uses these real locks: two tasks each need lock A and lock B.

How much memory has your OS promised?

    
Programs reserve memory before they use it. The OS adds all these promises (the commit charge) and refuses new promises above a limit, even if real memory is still free. Like the banker, it says no to keep every promise safe.

    Q2 · avoidance
    
Do it on your computer

      

      
  1. Ctrl+Shift+Esc → Performance → Memory.
  2. Read Committed, for example 14.2/23.8 GB: promised so far / the limit.
  3. Open a big app and watch the first number grow.

      
  1. Activity Monitor → Memory tab.
  2. Read Physical Memory, Memory Used and Swap Used at the bottom: macOS promises memory using swap as the reserve.

    

    
Think: the OS refuses a request while real memory is free. Is that a waste? What does the banker's algorithm gain by doing the same?

Which program would you close?

    
When everything freezes, you choose a program to close in Task Manager. The OS uses the same 4 questions to choose a deadlock victim: importance, work already done, data being modified, others depending on it.

    Q4 · recovery
    
Do it on your computer

      

      
  1. Task Manager → Details. Right-click a column title → Select columns → tick Base priority and CPU time.
  2. Look at 3 of your apps: priority, CPU time used, is one saving a file? does another app need it?
  3. Fill the table on the right.

      
  1. Activity Monitor → CPU tab → View → Columns: tick CPU Time.
  2. Look at 3 of your apps and fill the table on the right.

    

    
Think: why is closing the app that is saving a file the worst choice, even if it is the newest one?

A task that keeps being overtaken

    
Your browser runs small jobs in two queues. “Urgent” jobs (microtasks) always run before normal jobs (timers). If urgent jobs keep adding more urgent jobs, a normal job waits and waits: starvation, while the page is busy and not deadlocked.

    Q5 · starvation
    
Do it in this page
  1. Press Greedy: a normal job is scheduled “in 0 ms”, then urgent jobs flood the queue for 1.5 s.
  2. Press Fair: the same work, but each piece lets others pass (it yields).
  3. Compare how late the normal job ran.

    
Think: the fair version is like aging: the waiting job gets its turn after a while. What does the OS measure to decide when?
