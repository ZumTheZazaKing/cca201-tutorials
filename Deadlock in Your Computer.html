“(Not Responding)”: who is it waiting for?

When a window freezes, it is often waiting for another process. Windows can show you the wait chain: the same idea as a wait-for graph used to detect deadlock.

Q2b · detectionQ4 · resource graph

Do it on your computer

  1. Press Win + R, type resmon, Enter (Resource Monitor).
  2. CPU tab → right-click any process → Analyze Wait Chain.
  3. “not waiting” = fine. A list of threads = it waits for them. If the chain comes back to the first process, that is a deadlock.
  1. Activity Monitor → select an app shown as “Not Responding” → ⋯ → Sample Process: the report shows what its threads are waiting for.

Think: a chain A → B → C that ends is just waiting. When does waiting become a deadlock?

“The file is open in another program”

A file opened by one program is locked: another program cannot change or delete it. That is mutual exclusion. If two programs each lock one file and wait for the other's file, they deadlock.

Q1 · deadlockQ2c · prevention

Do it on your computer

  1. Open an Excel or Word file and leave it open.
  2. In File Explorer, try to rename or delete that file: “The action can't be completed because the file is open in…”
  3. Close the program and try again: it works. The lock was released.

Databases and OneDrive/Google Drive use the same idea when two people edit at the same time.

Think: if every program had to lock files in the same order (A before B), could a circular wait still happen?

Two devices talking at the same time

When two devices send on the same channel at the same time, the signals collide. If both wait exactly the same time and resend, they collide again and again: a livelock. Wi-Fi and Ethernet wait a random time to escape it.

Q1 · livelockQ5 · busy without progress

Do it on your computer

  1. Windows: Win + R → cmd → netstat -e: look at Errors and Discards.
  2. On a crowded Wi-Fi (library, hostel at night), run ping -n 50 8.8.8.8: lost packets and jumps in time are partly collisions and retries.

Think: why does adding randomness turn a livelock into normal work? Where else could you add randomness?

Low priority can mean never

Windows lets you set the priority of a process. With strict priorities, a low process only runs when nobody important wants the CPU. Windows prevents real starvation with a priority boost for threads that waited about 4 seconds: aging.

Q3 · detect starvation

Do it on your computer

  1. Task Manager → Details → right-click a program → Set priority → Low.
  2. Task Manager → Details → right-click a column title → Select columns → tick CPU time: it shows how much CPU each process got in total. A process with 0:00:00 for a long time is not served.

Think: which column would you watch to detect a starving process? What would you store in the PCB to compute it?

A hard disk going back and forth

A hard disk (HDD) moves an arm to the right track. If two programs keep asking for opposite ends of the disk, the arm travels most of the time: lots of movement, little useful work.

Q5 · disk arm

Do it on your computer

  1. Win + R → resmon → Disk tab → Storage: look at Disk Queue Length.
  2. Copy two big folders at the same time, then one after the other. On an HDD, doing both at once is often slower in total. (On an SSD there is no arm.)

Think: count the arm's trips per second for your own numbers. When is it a livelock and when is it only slow?
