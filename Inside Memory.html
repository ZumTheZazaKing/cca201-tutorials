Leftover space in a partition

A fixed partition of 40 K receives one job. Move the slider to change the job size and watch what is left over.

Then switch the unit: does "1 K" mean 1000 or 1024 bytes? It changes every number.

Think: if you only know the leftover, how do you get back to the job size? Can another job use that leftover?

Fixed vs dynamic

The same 120 KB of memory, managed two ways. On top: four fixed partitions of 30 KB. Below: dynamic blocks cut to the exact size. Load the jobs one by one.

Think: which scheme refuses a job? Where is memory wasted in each one? Which is simpler for the OS?

First-fit and best-fit, fixed partitions

You are the memory manager. For each job, click the partition the chosen algorithm would pick. If none fits, say so.

First-fit: the first partition, from the top of the list, that is big enough. Best-fit: the smallest partition that is big enough.

Think: which algorithm loads every job here? Which one wastes less memory?

Inside or between?

Two memories, both with wasted space. Click each red or grey area to see where it sits.

Think: give a name to each kind of waste. Which kind could be fixed by moving processes around?

Memory 1: fixed partitions of 30 KB

Memory 2: dynamic blocks, after some processes ended

Why compact?

A new process needs 100 KB in one piece. Count the free space, try to load it, then compact.

Think: did compaction create new memory? What did it change?

Two schemes, one memory

160 KB for user processes. Scheme A: four fixed partitions of 40 KB. Scheme B: dynamic blocks. Load the processes in arrival order and compare the counters.

Think: a scheme can have a lot of free memory and still refuse a process. Why?

First-fit and best-fit, dynamic blocks

Now the free blocks can be split: the process takes what it needs and the rest becomes a smaller free block. Click the free block the algorithm would choose.

Grey blocks are free; coloured blocks are already in use. Blocks are in address order, left to right.

Think: at the end, is the total free memory different between the two algorithms? What about the size of the biggest free block?

Freeing blocks

Click a process to end it. Its block becomes free and joins any free neighbour, left or right.

Think: how many different situations exist, depending on the neighbours? How do you get the start address and size of the new free block?

Keeping the free and busy lists

The memory manager keeps two lists. Step through the operations and watch both lists change: blocks are split on allocation and merged on release.

Before each step, write down what you expect. Then click Next.

Think: after a release, which algorithm leaves the biggest free block for a large process?

Compaction with relocation

A process needs 400 KB in one piece. Compact the memory: every process slides down toward address 200, and the OS records how far each one moved.

Think: why must the OS know how far each process moved? Why is the adjustment negative?
